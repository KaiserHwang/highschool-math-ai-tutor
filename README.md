# MathPulse 고1 수학 연습장

2022 개정 교육과정 **공통수학1·2**를 위한 수준 진단, 단원별 3단계 힌트 코칭, 오답 복습 웹앱입니다.
설치 없이 브라우저에서 열고, 태블릿에서는 홈 화면에 추가해 앱처럼 쓸 수 있습니다.

**바로 쓰기:** https://kaiserhwang.github.io/highschool-math-ai-tutor/

## 사용 순서

1. **수준 진단**을 먼저 봅니다(약 30분). 모르는 문제는 건너뛰는 편이 진단에 도움이 됩니다.
2. **오늘** 화면의 "다음 문제"를 풉니다. 풀던 단원을 이어서, 다 끝나면 숙련도가 낮은 단원을 트랙에 맞는 난이도로 추천합니다.
3. 막히면 힌트를 한 단계씩 엽니다. 그래도 모르겠으면 풀이 메모를 적고 **AI에게 묻기**를 누릅니다.
4. **오답 복습**에 빨간 숫자가 뜨면 그날 복습할 문제가 있다는 뜻입니다.
5. 보호자는 **리포트**에서 학습 현황을 확인합니다.

### 구독 AI 연결 방법

- **Claude, ChatGPT**: 버튼을 누르면 질문이 입력창에 채워진 상태로 새 창이 열립니다.
- **Gemini**: 질문이 클립보드에 복사되고 Gemini가 열립니다. 입력창에 붙여넣으세요.
- **전용 튜터 방(선택)**: 설정 → "튜터 지침 복사"로 지침을 복사해 Claude 프로젝트, ChatGPT GPT, Gemini Gem을 만들고 그 주소를 설정에 넣으면, 버튼이 그 방을 엽니다(질문은 클립보드로 전달).

각 서비스의 로그인은 그 서비스에서 평소처럼 합니다. 이 앱은 계정 정보나 API 키를 다루지 않으므로, 다른 사람이 주소로 들어와도 보호자의 AI 구독을 쓸 수 없습니다.

## 기록은 어디에 저장되나요

모든 기록은 **이 기기의 브라우저(localStorage)에만** 저장되고 서버로 보내지 않습니다. 다른 사람이 같은 주소로 접속해도 아드님의 기록은 보이지 않습니다.
브라우저 데이터를 지우면 기록도 사라지므로, 설정 → **백업 파일 내려받기**로 가끔 백업하세요. 다른 기기로 옮길 때도 백업 파일을 불러오면 됩니다. 백업 파일은 전체 구조를 검사한 뒤에만 반영하고, 형식이 맞지 않으면 기존 기록을 그대로 둡니다.

## 문제의 정확성

모든 문항의 정답은 `tests/verify_answers.py`, `tests/verify_extra.py`에서 **풀이와 다른 방법(전수 조사, 기호 계산, 수치 최적화)으로 다시 계산해** 데이터와 대조합니다. 객관식은 정답 보기가 계산값과 같은지, 다른 보기와 값이 겹치지 않는지도 확인합니다. 그림 문제는 그림 데이터(포물선의 계수, 점의 좌표, 도로망의 끊긴 길, 벤 다이어그램의 색칠한 영역)를 직접 읽어 정답을 계산하므로, 그림과 정답이 어긋나면 검사가 실패합니다.

비슷한 문제 생성기는 `tests/gen-check.mjs`가 유형마다 500문제씩 만들어 생성기와 다른 방법으로 정답을 다시 구하고, 수식 표기와 보기를 점검합니다. 문제를 추가하거나 고치면 이 검사들을 함께 갱신하세요.

교육과정 범위는 2022 개정 수학과 교육과정의 공통수학1(다항식, 방정식과 부등식, 경우의 수, 행렬)과 공통수학2(도형의 방정식, 집합과 명제, 함수와 그래프) 성취기준을 따릅니다. 외분점처럼 공통수학에서 빠진 내용은 다루지 않고, 행렬은 2×2 이하의 연산까지만 다룹니다.

## 구조

```
index.html                  앱 뼈대
assets/css/app.css          화면 디자인(밝게/어둡게, 인쇄)
assets/js/app.js            화면 전환(#/ 주소)
assets/js/store.js          기록 저장·백업
assets/js/model.js          채점, 숙련도, 역량, 추천, 복습 주기
assets/js/content/units.js  단원 개념 정리(그림 포함)
assets/js/content/bank/     단원별 문제 은행(u1.js ~ u8.js)
assets/js/content/generators.js  비슷한 문제 생성기
assets/js/content/diagnosis.js   수준 진단 문항
assets/js/views/            오늘, 진단, 단원, 문제, 오답, 리포트, 설정
assets/js/lib/              수식 렌더링, 그림 엔진(plot.js), 레이더 차트, 연습장, AI 연결
assets/vendor/katex/        수식 렌더러(KaTeX 0.16, 오프라인용 내장)
sw.js, manifest.webmanifest 오프라인 사용과 홈 화면 추가(sw.js는 tools/gen-sw.mjs로 생성)
tests/                      정답 검증, 생성기 검사, 콘텐츠 검사, 브라우저 종단 테스트, 그림 점검 페이지(gallery.html)
docs/SERVICE_PLAN.md        기획 문서
```

빌드 단계가 없는 정적 사이트입니다. GitHub Pages의 `main` 브랜치 루트를 그대로 배포합니다.

## 개발

```bash
python3 -m http.server 8080        # http://localhost:8080 에서 실행
pip install sympy && python3 tests/verify_answers.py   # 정답 검증
node tests/gen-check.mjs           # 비슷한 문제 생성기 검사
node tests/content-check.mjs       # 수식·HTML·그림 설명·서비스 워커 검사
node tests/unit.mjs                # 회귀 검사(백업 가져오기 검증, 캐시 정리, 시간대별 통계)
node tools/gen-sw.mjs              # 파일을 고친 뒤 서비스 워커 갱신
npm i --no-save playwright && npx playwright install chromium
node tests/e2e.mjs                 # 브라우저 종단 테스트(서버 실행 중일 때)
```

파일을 고치면 `node tools/gen-sw.mjs`로 서비스 워커를 다시 만드세요. 버전이 파일 내용의 해시로 정해지므로, 배포하면 사용자의 오프라인 캐시도 자동으로 새 버전으로 바뀝니다. `content-check.mjs`가 최신인지 검사합니다. 그림을 고칠 때는 `tests/gallery.html`에서 모든 그림을 한눈에 볼 수 있습니다. GitHub Actions(`.github/workflows/check.yml`)가 푸시할 때마다 다섯 가지 검사를 실행합니다.
